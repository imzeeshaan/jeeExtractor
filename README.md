# JEE Question Template Studio

Extracts questions, options, and answers from JEE exam PDFs — deterministic
text-layer parsing for standard MathonGo-style papers, with an AI vision
fallback (DeepSeek + OpenAI) for scanned papers (e.g. JEE Advanced) that have
no extractable text layer. Includes a Streamlit review UI for inspecting
low-confidence extractions, correcting them, and approving results.

## Requirements

- Python 3.9+
- macOS/Linux/Windows (developed and tested on macOS)
- (Optional, only for the vision fallback path) API keys for
  [DeepSeek](https://platform.deepseek.com/) and/or
  [OpenAI](https://platform.openai.com/)

## Installation

1. **Clone the repo**

   ```bash
   git clone https://github.com/imzeeshaan/jeeExtractor.git
   cd jeeExtractor
   ```

2. **Create and activate a virtual environment**

   ```bash
   python3 -m venv venv
   source venv/bin/activate        # Windows: venv\Scripts\activate
   ```

3. **Install dependencies**

   ```bash
   pip install -r requirements.txt
   ```

4. **Configure environment variables**

   Copy the example env file and adjust as needed:

   ```bash
   cp .env.example .env
   ```

   `.env.example` covers the basics (data directory, DB path, render DPI).
   To also enable the vision fallback path (only needed for scanned/JEE
   Advanced-style PDFs — standard papers work fully offline without this),
   add:

   ```bash
   DEEPSEEK_API_KEY=your-deepseek-key
   OPENAI_API_KEY=your-openai-key       # used as the fallback/escalation provider
   JEE_VISION_PROVIDER=real             # defaults to "mock" (no API calls, no cost)
   ```

   `.env` is git-ignored — never commit real API keys.

5. **Run the test suite** (optional, confirms the install is healthy)

   ```bash
   pytest tests/unit/ -q
   ```

## Running the app

There are two separate Streamlit entry points:

- **Original single-session extractor** — upload a PDF, get questions/answers
  back in one pass, no persistence:

  ```bash
  streamlit run app.py
  ```

- **Review Studio** — the full pipeline (ingest → template match → validate →
  review/correct → approve), backed by a persistent SQLite database at
  `data/app.db`:

  ```bash
  streamlit run review_app.py --server.port 8502
  ```

Both can run at the same time on different ports.

## Command-line usage

For scripted/batch ingestion without the UI:

```bash
python3 scripts/run_adapter.py --pdf path/to/paper.pdf --exam "JEE Main" --year 2020
```

To manually test the vision fallback against a scanned fixture (requires
real API keys and `JEE_VISION_PROVIDER=real`):

```bash
python3 scripts/run_vision_experiment.py
```

## Data

Everything ingestion produces (uploaded PDFs, rendered pages, cropped
images, the SQLite database) lives under `data/` and is git-ignored — it's
regenerated by ingestion, not checked into source control.
